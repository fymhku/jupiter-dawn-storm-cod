## 二、使用网页上传（不安装Desktop）

1. 打开原仓库，选择 `Add file → Upload files`。
2. 拖入解压后包**内部的文件和子目录**，使README直接出现在仓库根部。
   GitHub不会把上传的ZIP自动展开为代码目录，所以ZIP不能替代这一步。
3. `.gitignore`、`.gitattributes`是隐藏文件，资源管理器需显示隐藏项目，或分别添加。
4. 填写commit说明；若选择新分支，提交后创建PR并合并到准备发布的主分支。
5. 若浏览器达到单次文件数限制，分批上传。GitHub官方当前限制每批100个文件、单文件25MiB。
   本包的最大NPZ小于25MiB，仍应以实际上传界面的提示为准。

官方说明：https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository

## 三、建立GitHub Release

1. 代码已推送并核对后，打开仓库 `Releases → Draft a new release`。
2. `Choose a tag` 输入未使用的 `v1.1.0`，选择当前代码所在分支。
3. Title填：`v1.1.0 — Calibrated PSD and 2017 analysis package`。
4. Description可粘贴 `docs/RELEASE_NOTES.md` 内容。
5. 在附件区上传本次 ZIP 和 ZIP 对应的 `.sha256` 文件（外层说明不必上传）。
6. 核对后点击 `Publish release`。网页Code页保留可浏览的源码，Release提供固定版本下载。

官方说明：https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository

## 四、Zenodo：沿用原记录的新版本

旧引用是v1.0.1；这次包含PSD方法和文件更新，应建立新版本。
不要把旧版本记录上的版本号直接改成v1.1.0以假装已归档新代码。

方案A（原记录已由GitHub自动归档时优先）：

1. Zenodo登录后，从头像菜单进入 `GitHub`，点击 `Sync now`。
2. 确认原仓库的同步开关已启用；尽量在发布新GitHub Release之前完成。
3. 发布上面的新Release，等待Zenodo处理，再进入生成的软件记录。
4. 核对版本、作者、文件、许可证状态，以及是否与旧记录列在同一版本链。
5. 核对Zenodo实际保存的文件清单；不要假定所有GitHub Release附件都被自动归档。

官方说明：
https://help.zenodo.org/docs/github/enable-repository/
https://help.zenodo.org/docs/github/archive-software/github-upload/

方案B（原记录为手工上传，或需要手工更新文件）：

1. 打开你拥有的旧Zenodo记录 https://zenodo.org/records/23184052 。

同一个版本选择一种归档路线，避免自动归档和手工新版本同时生成两份重复记录。
官方说明：https://help.zenodo.org/docs/deposit/manage-versions/
